Fusionner une branche d'essai sans reprendre toute l'exploration

Un scénario réel exécuté avec la bibliothèque : une recette de référence à 5 étapes sur main, une branche essai-cuisson pour faire varier l'étape 3 (température de cuisson) sur trois commits, puis une fusion qui ne rapatrie que cette étape — chaque autre différence est résolue manuellement, chemin par chemin.

Resolution de la fusion

follow merge main essai-cuisson --take-steps "[2]"

Pendant que la branche explorait la cuisson, main a evolue de son cote (un melange plus long, etape 1). Les deux lignes divergent donc sur deux etapes — Follow ne choisit rien automatiquement : chaque etape en conflit est resolue explicitement.

Intention

Combiner le melange ameliore (main) et la temperature de cuisson validee sur la branche d'essai, sans reprendre le reste de l'exploration.

Parents (commit de fusion — deux ascendances)
baseline · mainexp_22fbd7b0 — Melange plus long
merge_source · essai-cuissonexp_a7dba56e — Essai a 175C
Conclusion

Recette consolidee : melange 4 min + cuisson 175C/32min. Les essais a 160C et 185C restent tracables sur la branche essai-cuisson pour reference future.

Reproduire

Les memes commandes, en CLI

# apres les 3 commits sur la branche essai-cuisson…
follow diff main essai-cuisson --repo labo --steps
~ [2].parameters.temperature: 170 C -> 175 C
~ [2].parameters.duree: 35 min -> 32 min

follow merge main essai-cuisson --repo labo \
  --title "Fusion : temperature de cuisson optimisee" \
  --intent "Adopter la cuisson validee sans reprendre le reste" \
  --take-steps "[2]" --out merge.json

follow commit merge.json --repo labo
